# KNOWN_LIMITATIONS.md

Engine-level gaps verified against official documentation (see BEDROCK_COMPATIBILITY.md). “Shipped approximation” means the gameplay-facing behavior now exists, but the Java-only mechanism does not.

1. **OS-level integration remains impossible** — Bedrock cannot change the native window title, open LWJGL/JFrame dialogs, create desktop files, or crash the process. The in-game title/form surrogates remain (A-004).
2. **The Java GLSL pipeline remains impossible** — Bedrock cannot load the mod's 89 Java core/post shaders. Chunk 20 ships the supplied VHS pack as a valid JSON UI HUD overlay, four severity subpacks, and Vibrant Visuals atmosphere/color/lighting/shadow settings. Aberration, invert, dream, fever, and glitch effects remain mood-level approximations (A-003).
3. **Custom fluid physics remain unavailable** — `void_liquid` uses the existing translucent block/script approximation (A-001).
4. **Custom mob-effect registry entries remain unavailable** — `heart_corruption` and `why_cant_you_leave` now run as finite script effects. The latter uses the original eyes texture through a native Bedrock particle. A custom potion icon and Java's `MAX_HEALTH -1` attribute modifier cannot be reproduced exactly (A-002).
5. **Custom advancements remain unavailable** — the existing progression flags and toast-style presentation are the shipped replacement (A-006).
6. **Custom painting variants remain unavailable** — Chunk 20 ships `circuit_cave` as a breakable 4×2 decorative entity with the original 128×64 texture and a consumable placement item (A-005).
7. **Noise-based custom terrain generation remains unavailable** — the dimension terrain and structures remain supported approximations (A-007).
8. **Beta APIs are required by the shipping behavior pack** — the effective pack floor is Bedrock 1.26.50 and the BP declares `@minecraft/server` `2.11.0-beta`; worlds must enable Beta APIs. Dimensions are retained.
9. **Custom Java font glyphs are unresolved** — corrupted text uses Bedrock formatting and standard glyphs. The Java font map cannot be copied safely without a verified Bedrock glyph-page mapping (A-009).
10. **Packet-level desynchronization is impossible** — the Java desyncer suppresses and later resends network packets. Bedrock exposes no packet interception API, so the item ships a nausea/darkness/glitch/resync gameplay surrogate (A-010).
11. **Java-mod compatibility mixins are inapplicable** — Iris/Oculus/Sodium/JourneyMap/Xaero/EMI/JEI/Jade/VoiceChat/DistantHorizons integration has no Bedrock runtime equivalent.
12. **`sites/rblog/file.bin` stays out of the pack** — it is an opaque 85 MB non-Minecraft payload and cannot execute in Bedrock.
13. **Nostalgia overrides remain partial/deferred** — these replace broad vanilla sound/model assets and can conflict with the main RP. The later `tbs.zip` upload is a multipart/concatenated archive whose outer directory exposes only chunks 3, 5, 6, 7, 8, and 9, so it is not a safe basis for claiming a complete optional-pack import.

14. **Integrity Java transport and presentation are not exact** — the Arena runtime now owns source-backed participant selection/liveness, phase transitions/transfers, tentacle placement, boundary countdown, native void terminal damage, GroundAttack/GroundArm timing/owner/lifecycle adaptation, the complete Phase3Goals multi-attack selector, roster-isolated player/fireball damage gates, mace parry, source AABB contact, supported free-camera/fade calls, and 298-tick delayed cleanup. Java's transition.png overlay packet, custom music/cutscene packets, exact client camera interpolation/zoom transport, custom void_mass death-type metadata, synchronized integer owner field, and custom dying animation remain adaptations or unsupported transport (A-011, A-013, A-018).

15. **Jimmy attack animation and particle presentation are adapted** — Chunks 28, 33, 35, and 37 preserve the recovered attack names, source keyframe times, deterministic 20 Hz event ticks, rising damage wave, damage contract, direct Bedrock animation playback, locator-bound visual contact effects, the source Jimmy spawn cue, and SoundInstance-backed JimArena intro/loop cleanup. Server-side limb/world-bone origins remain explicit spatial adapters because the Script API has no rendered-bone transform getter; the Rock block-impact burst uses a source-counted moon-stone Bedrock emitter, with emitter lifetime/physics as the remaining particle difference (A-015, A-017, A-019, A-021, A-024).

16. **Jimmy multipart and FracturedRoam host hierarchy are adapted** — Chunks 29–31 preserve the six logical part dimensions/offsets, distinguish FracturedPartEntity head/chest behavior from FracturedSubEntity leg delegation, apply the source-specific positive/negative body-yaw transforms, guard Roam promotion until its 149-tick RISING state reaches NORMAL, preserve the 103-tick SWITCHING duration, and adapt the underground/dig/despawn/recovery lifecycle plus JimArena schedule. Chunk 35 adds the source Spawn/Idle/Walk/Flee/Underground/Loss presentation mapping, and Chunk 37 adds the source Jimmy spawn cue plus SoundInstance-backed intro/loop cleanup on arena reset. Bedrock uses a root collision envelope plus deterministic swept conceptual AABB filtering because it has no Java child part entities or parent/part identity. Exact rendered-bone contact and exact ordinary-melee hit location remain unsupported because [EntityHurtBeforeEvent](https://learn.microsoft.com/minecraft/creator/scriptapi/minecraft/server/entityhurtbeforeevent?view=minecraft-bedrock-stable) exposes no impact coordinate; bossbar/camera packets and exact Java fade/attenuation remain unsupported or deferred (A-016, A-019, A-021, A-024).

17. **Java custom damage-type registration is unavailable** — the port catalogs all 15 source definitions, verifies their extracted JSON/tag flags, maps each id to a documented native Bedrock cause/attribution shape, and preserves every same-tick source record per target. Custom death messages, exhaustion/scaling rules, no-knockback behavior, and exact armor/effect/invulnerability/shield/totem bypass semantics cannot be installed through the current Script API (A-018, A-025).

18. **Java particle providers and custom render hooks are adapted** — Chunk 36 ships all nine declared particle resources and source textures, preserves the registered provider sizes/lifetimes/render-sheet choices, and moves source event counts/spread into Bedrock emitters because Dimension.spawnParticle accepts an effect id and origin. Paper's crossed-quad custom renderer is a billboard/dynamic-motion adapter, while follows_particle and revuxor_particle remain resource-only because no registered Java providers were found (A-020).

19. **NullBookStoryEvent uses a Bedrock book-component adapter** — Java's `WrittenBookContent` data component is not directly installable from Bedrock scripts. The port uses the supported `minecraft:book` `ItemBookComponent`, preserves Java coordinate conversion, clones copies per player, drops inventory leftovers, and uses bounded logged retries; exact Java component serialization remains an adapter detail.
20. **P1 custom-dimension terrain is not exact** — all 13 source IDs, entry policies, registration, readiness, safe landing, and supported return routes are retained, but the current `DimensionRegistry.registerCustomDimension` surface cannot install Java `noise_settings` or arbitrary `ChunkGenerator` implementations (A-026).
21. **P1 structure placement remains partly adapted** — the full 314-template source corpus and supported Shaft connector graph are inventory- and validation-gated, with six source-identical Shaft assets staged. Java custom generators/processors, exact Stage 2/XCSF placement, and in-game natural frequency/spacing remain unavailable without an engine world sample (A-027).
22. **P1 block-entity and tag internals use adapters** — eight source block-entity equivalents, supported block tags, shears matching, dynamic-property state, and scripted consumers are checked, while Java-only NBT/storage/tick internals and item-tag registry semantics are not universally exposed by the pinned Bedrock ABI (A-028).
23. **P1 portal entity scope is narrower than Java** — player-click linking, persistent anchors, readiness-gated safe arrival, fallback, and one-tick cooldown are shipped. The current Bedrock route does not claim Java's same-dimension living-entity tick sweep or item/projectile transfer hooks (A-029).
24. **P1 vanilla loot output identifiers use adapters** — the current project validation surface cannot resolve the Java `minecraft:cobblestone_stairs` and `minecraft:oak_door` outputs as behavior-pack item definitions, so their source conditions/weights route through the supported custom block forms and are explicitly release-gated (A-031).
25. **P1 presentation parity remains partly engine-limited** — the source-backed audit now covers 35 animation files, the seven registered Java particle providers and their extracted callsite families, 9 particle definitions, all shared sound cues plus 12 jukebox songs, 10 record items, ten Java menu registrations, and the three deployed UI files. Several provider/callsite families still need dedicated Bedrock runtime bridges, while `video/alpha3` remains intentionally source-only. Bedrock record comparator strength is capped at 13 and custom string sound events require the pinned Beta API; Java GeckoLib controller/render-bone transforms, exact lag-visible keyframe contact, FancyAudio/reload mixing, multiplayer HUD smoke behavior, custom glyph pages, and the Java GLSL pipeline remain approximation, deferred, or unsupported (A-032).

26. **Null Maze/Flying Java AI is adapted pending engine evidence** — `NullMazeEntity.java`'s custom `StalkGoal`, `MazeNavigator`, `MazeHitGoal`, exact door ray, stuck destroy branch, and `NullFlyingEntity.java`'s server trigger are represented by source-backed models, native Bedrock goals, `getBlockFromRay`, command-backed drops, and the event-driven controller. `PlayerUtil__PlayerCheckDSLKt.java`'s strict eye-center gaze and `PlayerExt.java`/`ClientPlayerDSLKt.java`'s FOV formula are preserved in pure/runtime helpers. Bedrock has no server client-FOV option, custom Maze pathfinder, Java door geometry, custom damage type, or exact swing hook; custom doors therefore use open-state permutations. Collision, navigation, sound, damage, multiplayer, save/reload, and FOV still require the exact 1.26.50 Preview runtime report (A-033).

27. **Java chunk storage and forced-ticket operations are unavailable** — `ChunkRemoverConditions.java`, `ChunkRemoverEntity.java`, `ChunkHelper.java`, `ChunkUtil.java`, and `ChunkCommands.java` are represented by ordered source gates, a persistent modified-chunk ledger, loaded-chunk `fillBlocks`, top-down `clone ... move` sections, and guarded entity teleports. Bedrock owns chunk block entities, scheduled ticks, light updates, chunk packets, and ticket state; it does not expose raw chunk-section mutation or a Java-equivalent force-load/unload lifecycle. The `LightLayer.BLOCK` gate is conservatively mapped to total brightness, and unloaded targets fail closed. Force-load callsites (`StructureUtil.java`, `CorruptedCommandBlockHandler.java`, and `LevelLoadHandler.java`) remain normal-engine loading behavior rather than unsupported low-level calls (A-034).

28. **Numeric provenance has explicit engine boundaries** — `LOSS_HUGE` regain uses Java's integer-half result `17`; `13000` and `24000` are recovered `TimeOfDay.java` values, while `23000` is a Bedrock event-gate adapter. The `1e-9` swept-AABB epsilon and `0.999999999` exclusive-roll clamp are Bedrock numerical adapters with no claimed Java literal (A-035).

All reachable Java behavior is either implemented, approximated with an explicit player-visible difference, or retained here as engine-unsupported.
